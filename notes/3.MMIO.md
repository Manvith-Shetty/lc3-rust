What are the example codes reserved for devices?
1. KBSR i.e. Keyboard Status Register
Address: 0xFE00 — read only
Tells you whether a key has been pressed. Bit 15 is the "ready" flag: 1 means a character is waiting, 0 means nothing yet. A program spins on this address until the bit turns on. It says nothing about which key but only status.

2. KBDR i.e. Keyboard Data Register
Address: 0xFE02 — read only
Holds the actual character. Bits 7–0 are the ASCII code, bits 15–8 are always zero. Only meaningful when KBSR's ready bit is set. Reading it consumes the keypress, which clears KBSR back to 0 so the same key isn't read twice.

3. DSR i.e. Display Status Register
Address: 0xFE04 — read only
Tells you whether the screen is ready to accept another character. Bit 15 set = ready. Real hardware needs this because a terminal can't take characters faster than it can draw them; in a VM writing to stdout, it's always ready, so you just return 1 << 15 unconditionally.

4. DDR i.e. Display Data Register
Address: 0xFE06 — write only
Storing a value here prints it. Bits 7–0 are the ASCII code to display; the high byte is ignored. This is the actual output mechanism the OUT trap routine uses underneath.

5. MCR i.e. Machine Control Register
Address: 0xFFFE — read/write
Bit 15 is the clock enable. While it's 1 the CPU keeps fetching instructions; the moment a program clears it to 0, the clock stops and the machine halts. This is what TRAP HALT really does — print a message, then clear this bit.

The pattern in which the above MMIO work are
1. Status-data pair: A status register you poll and data register to actually read the data or write to. 
Check status, then touch data. KBSR→KBDR for input, DSR→DDR for output.

2. Ready lives in bit 15. Not bit 0. Bit 15 is the sign bit of a 16-bit value, so a program can test readiness with a single conditional branch on the negative flag — BRzp loops while not-ready. Putting the flag anywhere else would need masking first.
