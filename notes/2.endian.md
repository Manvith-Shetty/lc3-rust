## Notes

1. Basically endianness means the order in which the bytes in multibyte value are stored or interpreted. This operates on byte level. Suppose you have a single byte 0000 0010 then this remains same. But incase of a u16 number 0x1234 (each hexadecimal number represents 4 bits 0-16 so) then we have 0x12 (MSByte) & 0x34(LSbyte). 
2. Big-endian means Store most significant byte first. Therefore, 0x1234.
3. Little-endian means Store least significant byte first. Therefore, 
  Address     Byte
  1000      0x34   ← LSB
  1001      0x12   ← MSB
4. What does LC-3 uses to represent? It uses big-endian in its specs so the LC-3 object file stores it that way.
5. I can't use my computers native endianness as im using macbook pro m4 which uses ARM64 architecture, this is little-endian mode by default.
6. So when I'm loading the the object file for my LC-3 vm, I load u16 2 bytes and have them stored in Big endian format in VM's memory.
