## Notes

1. A VM is program acting like a real computer. This is completely software defined. If can emulate the computer as needed for the working.
2. Why? Assume I have deployed a smart contract to the ethereum blockchain. Now the bytecode generated is executed by the Ethereum virtual machine (EVM). This EVM has its own instruction set like: PUSH, ADD, SSTORE, SUB etc. So the code deployed should be run by thousands of nodes which could be running Linux x86, Linux ARM, Windows x86, Mac ARM etc so if the contract directly contained x86 machine code, this would have failed to execute in ARM architecture. Thus the contract is executed by this EVM as a virtual computer.
3. Security - Using this we can execute smart contract written by complete stranger. This EVM has access to only contract code, stack, memory, strorage etc and no access to file system, disk, network etc.
4. Why dont we use compiler? Different scope (few does overlap thou). Suppose I have my own programming language. Now if I want to create machine code for different cpu arch I need different compiler backends. Now we can use that approach to create machine code. Or have comiple into our own byte code will run on our vm. The program remains the same.
5. The downside of above being performance. A single instruction of my VM like JVM might require many cpu instructions of the host machine. (Can optimize via JIT which the VM says "This code is being executed thousands of times. Instead of interpreting it every time, I'll compile this frequently-used bytecode into native machine code".
6. Incase of Garbage collector, So the VM gives the runtime a controlled environment where it can observe and manage program execution like what JVM does.
